## 1.0.289 — 16 November 2026

**The database on a server of its own, looked after by otp-db-agent** (isemon's external-database kit, 2nd edition) - layout A: one otp node, or two that share one database, and its database server. Without an agent nothing changes: no file `/var/lib/otp/db-agent/agent.json`, every path as it was. docs/external-database.md.

- **`install.sh --db-server postgres|mariadb`** on the database server: PostgreSQL 16 (AppStream's module or PGDG; Debian/Ubuntu PGDG) or MariaDB installed, initialised, secured, the database and its account, the otp nodes let in (`--otp-node`: pg_hba.conf written link-safe, firewalld), **otp-db-agent** and a join code. **`--db-agent`** the agent alone, or upgraded (its nodes stay joined, no code printed; `--new-code` for one). Passwords from `--db-password-file`, never asked on a command line; `--dry-run` masks them.
- **`otp --db-agent-join -`** on the node (the code on standard input - one on the command line is refused), or *Settings → The database → Connect a database server…* (also from the first step of *Move to another database*): the agent's certificate pinned from the code, the code's secret and the node's signing key sealed to the agent's own key, a client certificate from otp's authority.
- Through the agent, while this node's database is on its server: Database → TLS (the server's certificate from otp's authority, ssl on, verify-full, renewed), the server's own settings told and restarted, PostgreSQL's state, a node at a new address let in before the network changes, MariaDB's certificate (*Turn TLS on*, `otp --db-agent-mariadb-tls`).
- **The card *Database server***: where the database is, the server's tile (engine, running, TLS, connections, disk, RAM, load, uptime, both certificates' ends, nodes not heard from, an agent of another program), *Look now*, *Renew the certificates*, *Restart the database…*, *Forget the agent…*; a pill naming the server on the cards whose work reaches it (Database → TLS, the server's own settings, the firewall), its row on Database → TLS.
- `otp --db-agent-status [--json]`, `--db-agent-renew`, `--db-agent-restart`, `--db-agent-mariadb-tls`, `--db-agent-forget --yes`, `--db-agent-leave --yes`; a line in `otp --status`. Alerts (in Czech too): the agent does not answer, its database does not run, its certificate or this node's not renewed, the agent another program than this otp ships. Prometheus: `otp_db_agent_up`, `otp_db_server_up`.
- The agent: two processes (the side facing the network a program of its own as `otp-db-agent`, no key - root checks, does and signs), both ends pinned, every request and answer signed (a nonce never seen, also across a restart), a closed set of operations, the server's certificate one cluster's, every refusal audited without a secret, its certificate renewed by itself with an overlap, a hardened unit.
- MariaDB asked for TLS (`db_tls` require / verify-*) never goes on in the clear: a server that does not offer TLS is refused (PyMySQL went on unencrypted).
- Later releases: high availability with each node's database on a server of its own (layout B), the move wizard's *make it for me* on the agent's server, this machine's database shown as a database server, the servers in the header's meter.
